# CRM for services

Лендинг персонального Telegram-бота онлайн-записи с формой заявок и защищённой мини-CRM. Проект рассчитан на PHP 8.2+, MySQL 8 и Apache; Node.js, сборка и внешние CDN не нужны.

## Структура

- `index.php` — лендинг;
- `app/site-content.php` — цены, ссылки, контакты, FAQ и основные тексты;
- `config/config.php` — локальные секреты и параметры окружения (не попадает в Git);
- `submit-lead.php` — серверная обработка заявки;
- `admin/` — вход, список, поиск, фильтры, карточка заявки и CSV-экспорт;
- `database/schema.sql` — схема MySQL;
- `assets/` — стили, JavaScript и оптимизированные изображения;
- `media/` — неизменённые исходники изображений;
- `privacy.php`, `consent.php`, `terms.php` — документы.

## Локальный запуск

1. Установите PHP 8.2+ с расширениями `pdo_mysql` и `mbstring`, MySQL 8.
2. Создайте БД:

   ```bash
   mysql -u root -p < database/schema.sql
   ```

3. Скопируйте `config/config.example.php` в `config/config.php` и заполните параметры БД, адрес сайта и секретный ключ.
4. Создайте хеш пароля администратора:

   ```bash
   php -r "echo password_hash('ВАШ_СЛОЖНЫЙ_ПАРОЛЬ', PASSWORD_DEFAULT), PHP_EOL;"
   ```

   Вставьте результат в `admin.password_hash`. Сам пароль в файл не записывайте.
5. Запустите сервер из корня проекта:

   ```bash
   php -S localhost:8080
   ```

6. Откройте `http://localhost:8080/`. Мини-CRM: `http://localhost:8080/admin/`.

Встроенный сервер PHP подходит только для локальной проверки. Правила `.htaccess` в нём не применяются.

## Настройка контента

В `app/site-content.php` замените:

- `links.demo_bot` — ссылка на тестового бота;
- `links.developer` — ссылка на Telegram разработчика;
- `contacts.telegram` и `contacts.email`;
- цены в `pricing` (все выводы цены на лендинге берутся только отсюда);
- юридические реквизиты в `legal`;
- при необходимости тексты, FAQ и этапы.

В `config/config.php` замените:

- `app.base_url` на адрес с `https://` без завершающего слеша;
- `app.key` на случайную строку не короче 32 символов;
- параметры MySQL;
- логин и хеш пароля администратора;
- необязательный `LEAD_NOTIFY_WEBHOOK_URL`.

Также замените `https://example.ru` в `robots.txt` и `sitemap.xml` на реальный домен.

## Webhook

Если `lead_notify_webhook_url` пуст, заявка всё равно сохраняется в MySQL. При заполненном URL после сохранения отправляется JSON `lead.created`. Сбой webhook не отменяет заявку. Секретов в JavaScript нет.

## Загрузка на SpaceWeb

1. В панели SpaceWeb создайте сайт, базу MySQL и пользователя базы.
2. Выберите PHP 8.2 или новее и включите расширения `pdo_mysql`, `mbstring`.
3. Импортируйте `database/schema.sql` через phpMyAdmin. Если база уже создана в панели, импортируйте только команду `CREATE TABLE` и предварительно удалите из SQL строки `CREATE DATABASE`/`USE` либо выберите нужную БД перед импортом.
4. Загрузите содержимое проекта в корневую папку сайта (`public_html` или папку, указанную в панели). Папки и `.htaccess` должны сохраниться.
5. На сервере создайте `config/config.php` из примера и внесите реальные значения. Не публикуйте его и не отправляйте в репозиторий.
6. Подключите домен, выпустите бесплатный SSL-сертификат в панели и укажите HTTPS-адрес в `app.base_url`, `robots.txt`, `sitemap.xml`.
7. Проверьте главную страницу, отправку формы, вход в `/admin/`, смену статуса и CSV-экспорт.

## Безопасность и обслуживание

Форма использует CSRF, honeypot, серверную валидацию, ограничение частоты по хешу IP и prepared statements. Админ-панель использует `password_hash`/`password_verify`, безопасные сессии и CSRF для изменений. CSV защищён от formula injection.

Рекомендуется:

- делать ежедневный дамп MySQL и хранить несколько независимых копий;
- резервировать `config/config.php` отдельно в защищённом хранилище;
- обновлять PHP в поддерживаемой ветке;
- периодически проверять HTTPS и форму;
- не хранить резервные копии в публичной папке сайта.

Пример дампа:

```bash
mysqldump -u USER -p DATABASE > crm-backup.sql
```

## Перед публикацией обязательно заменить

- домен `example.ru`;
- Telegram-ссылки и контакты;
- реквизиты оператора, адрес, email и ИНН;
- MySQL-доступ, `app.key`, логин и хеш пароля администратора;
- тексты и цену, если коммерческие условия изменились;
- ссылки и формулировки документов после проверки у профильного юриста.

Юридические страницы являются аккуратными базовыми шаблонами, но не заменяют юридическую консультацию для конкретного бизнеса.
